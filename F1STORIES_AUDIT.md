# F1Stories UI + Performance Audit

## 1. Executive Summary

F1Stories is a generated static site built with Node scripts, HTML, layered CSS, and vanilla JavaScript. Its shared navigation, editorial layouts, theme switcher, consent flow, article templates, and Data Hub are visually coherent at the inspected mobile, desktop, and tablet sizes. No P0 visual failure, page-level horizontal overflow, broken navigation drawer, or theme regression was found.

The strongest opportunities are delivery and maintenance issues: the homepage creates a YouTube iframe before the visitor asks for it; Dirty Air downloads a 1.8 MB all-season cache; Qualifying Gaps can drive OpenF1 into HTTP 429 retries; current article images lack compact responsive variants; two standings bundles exceed their recorded budgets; and a normal build changes 358 committed/generated files even though `build:check` reports synchronization. Repository-only waste includes an empty `Light` file, two HTML backups, an unreferenced `.build/pages` mirror, and about 48.85 MB of byte-identical article media copies that require a reference-safe investigation.

The full public build succeeded in an isolated copy with 1,981 files and 142.43 MB in `dist/`; its YouTube RSS refresh returned HTTP 404 after retries and correctly retained the checked-in snapshot. `build:check`, asset checks, static guards, public runtime audit, public image budget, author tests, standings tests, build tests, article-media guard, and consent guard passed. Static quality reported 99 of the allowed 100 `!important` declarations. `perf:budget` failed for `standings/standings.min.js` (+11.1%) and `standings/tabs/tyre-pace.min.js` (+10.6%). Blog taxonomy tests passed, but five golden HTML fixtures failed. The working repository was restored after testing; only this report's working-tree content differs, while the pre-existing staged addition of this file and staged deletion of `VISUAL_AUDIT.md` remain untouched.

## 3. Mobile Findings

### P0

None observed.

### P1

- **High — Homepage third-party work starts without intent.** On `/` at 390×844, scrolling the lazy iframe into range created YouTube/Google requests for embed scripts, CSS, three Roboto font resources, image/API/log traffic, and iframe execution. Root cause: the literal iframe in `index.html:248`; see PERF-001.
- **High — Dirty Air transfers the whole season.** Opening `/standings/?tab=dirty-air` fetched `standings/dirty-air-cache.json` at 1,905,227 transferred bytes for 14 sessions, although one session is rendered. Root cause: `loadDirtyAirCacheBundle()` populates every session at once; see PERF-005.
- **High — Qualifying Gaps reaches rate limits.** The tab produced five HTTP 429 responses across chunked `drivers` and `session_result` OpenF1 requests while still rendering from partial/cached data. Root cause is the parallel endpoint fan-out plus short retry pacing; see PERF-006.

### P2

- **High — Filter-removal controls are short touch targets.** At 390 px the active filter chip measured about 141×32 px and “Καθαρισμός φίλτρων” about 136×30 px. The filter options themselves are 40 px high. CSS explicitly sets 32/30/40 px minimum heights in `archive-editorial.css`; see UI-001.
- **High — Current article cards lack compact variants.** Recent entries such as `20260914W` have no `1-card.webp`; the archive/home payload falls back to the public 217,060-byte hero even when rendered near thumbnail size. The card-path helper already supports the missing file; see PERF-002.
- **High — Article hero preload can download the fallback beside AVIF.** On `20250901G`, HTML preloads `2.webp` (259,792 bytes) while its `<picture>` selects `2.avif` (177,356 bytes), producing two image transfers in the observed cold load. See PERF-003.
- **High — Mobile heroes have no intermediate source.** The image variant generator makes only full AVIF and 400 px card files for hero images; an article hero at roughly 344 px therefore receives the full public hero (up to the 300 KB guard). See PERF-004.

### P3

- **High — The legal contents strip hides later destinations.** At 390 px, the last link began at x=388 and ended at x=474. Horizontal scrolling works and no page overflow occurs, but the initial state gives no visual cue that more links exist. Root cause: `.legal-toc` uses clipped horizontal overflow with no edge affordance; see UI-002.
- **High — Authors requests a missing implicit favicon.** `/authors/` generated `GET /favicon.ico` with status 404 because its head has no favicon link, unlike the other shared shells. See UI-003.

The mobile homepage, archive cards, article typography, media iframe, table scroll region, Data Hub charts, authors grid, 404/offline states, navigation drawer, cookie disclosure/actions, and both themes otherwise remained usable without document-level overflow at 390 px. The 480 px article table and wide chart timelines scroll inside their intended containers.

## 6. Systemic Visual Findings

- **P2 / High:** Archive control sizing is systemic because `.author-chip`, `.category-chip`, `.active-filter-chip`, and `.filter-reset-btn` share one styling block. One shared-rule task covers unfiltered and filtered archive states (UI-001).
- **P3 / High:** Legal horizontal navigation behavior is owned entirely by `.legal-toc` in `styles/legal.css`; privacy and terms should receive the same fix (UI-002).
- **P3 / High:** Favicon declarations are inconsistent between shared page shells. Authors is the observed failure; keep the repair scoped to its head/template (UI-003).
- No systemic gutter, typography, theme-token, header, footer, card-radius, or document-overflow defect was found across the representative routes.

## 7. Runtime Bloat

- **Definitely unnecessary:** eager YouTube iframe activation causes a large third-party execution/request tree before a visitor elects to play the episode (PERF-001).
- **Definitely oversized for the rendered state:** Dirty Air transfers 1,905,227 bytes containing 14 complete sessions to render one selected session. Individual serialized sessions range from about 22 KB to 340 KB (PERF-005).
- **Definitely duplicated in one cold load:** the table article can preload WebP while `<picture>` selects AVIF, totaling 437,148 bytes for one hero (PERF-003).
- **Definitely avoidable:** both redirect bridges load the 1,450-byte error beacon and 619-byte theme initializer before a zero-second external redirect; only the 208-byte redirect helper is behaviorally required (PERF-007).
- **High-confidence delivery gap:** the public artifact keeps images below 300 KB, but recent articles missing `-card` files use 121–217 KB public heroes for small cards. The existing generator and payload format already support 400 px cards (PERF-002).
- **High-confidence responsive gap:** hero generation lacks a mobile-width source, leaving small viewports on the public full source (PERF-004).
- **Observed reliability/runtime work:** Qualifying Gaps produced five HTTP 429 responses and retries. Shared caching exists, but there is no in-flight request map and the two endpoint chains run concurrently (PERF-006).
- **Supporting evidence only:** article CSS coverage was low for `blog-styles.min.css` (4%) and Bootstrap (16%). Dynamic states were not classified as dead from coverage alone; PERF-008 and PERF-009 are investigation-first tasks.
- **Confirmed budget failures:** `standings.min.js` and `tyre-pace.min.js` exceed the recorded 10% growth threshold (PERF-010, PERF-011).
- **Possibly inconsistent offline work:** `sw-register.min.js` is linked only by authors, privacy, and terms even though the service worker precaches the homepage, archive, standings, and offline shell. PERF-013 requires behavior verification before broadening registration.

## 8. Repository Bloat

- **Definitely unused:** tracked zero-byte `Light`; no references (CLEAN-001).
- **Definitely excluded from runtime:** two tracked `article.html.bak` files, not copied to `dist/` and not referenced (CLEAN-002).
- **Definitely duplicated:** 13 tracked files under `.build/pages/` mirror root/page shells, total about 628 KB, have no repository references, and are excluded from `dist/` (CLEAN-003).
- **Possibly removable after reference audit:** 315 byte-identical media hash groups contain about 48,852,658 excess bytes. Many are intentional `1`/`2` naming copies or reused editorial media, so CLEAN-004 is an investigation and must not bulk-delete files.
- **Generated-state drift:** isolated build output differed from 358 existing files, including 349 under `blog-module`, while `build:check` passed because it inspects the current worktree instead of running a build and comparing a clean snapshot (CLEAN-006).
- **Stale test expectations:** five article golden fixtures fail while taxonomy tests pass (CLEAN-005).

## 9. Dependencies / Third-party Findings

Every declared package has a current build, parsing, optimization, testing, or audit use: `adm-zip`, `mammoth`, `sharp`, Font Awesome source data, Bootstrap Sass, `chrome-launcher`, `esbuild`, `fast-xml-parser`, Lighthouse, Lightning CSS, Playwright, Puppeteer, and Sass. No dependency-removal task is justified.

Third-party runtime is limited but meaningful. YouTube's iframe is the largest avoidable tree (PERF-001). OpenF1 is essential to the Data Hub, but current Qualifying Gaps pacing can trigger rate limits (PERF-006). Analytics is consent-gated correctly: the automated guard confirmed rejection blocks analytics and acceptance loads `gtag`. The social provider emitted one console error after activation, so PERF-012 is investigation-only. The build-time YouTube RSS endpoint returned 404; the fallback snapshot prevented a build failure, so no runtime task is required.
