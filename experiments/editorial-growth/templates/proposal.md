# Πρόταση συντακτικού πειράματος

Συμπληρώνεται από τον υπεύθυνο πριν από την αλλαγή. Το παρόν είναι σχέδιο, όχι έγκριση ή εντολή δημοσίευσης.
Δημόσιο repository: χωρίς πραγματικά analytics, αναζητήσεις, στοιχεία επισκεπτών ή μυστικά.

- **ID (`id`, EG-YYYY-NNN):** …
- **Υπεύθυνος (`owner`):** …
- **Θέμα (`topic`):** …
- **Canonical URL (`urls`, μόνο https://f1-stories.gr/):** …
- **Υπόθεση (`hypothesis`):** Αν αλλάξουμε …, ίσως παρατηρήσουμε …, επειδή …
- **Είδος αλλαγής (`changeType`):** …
- **Συμπεριφορά στόχος (`targetBehaviour`):** …
- **Μηχανισμός (`mechanism`):** Πώς θα μπορούσε η συγκεκριμένη αλλαγή να επηρεάσει τη συμπεριφορά; …

## Κύριο αποτέλεσμα (`primaryOutcome`)

- **metric:** σταθερό αναγνωριστικό lowercase snake_case, π.χ. `internal_page_click` …
- **unit:** ακριβής μονάδα, όχι «αναγνώστες» για GA4 συμβάντα …
- **source:** `gsc` / `ga4` / `rum` / `repo` …
- **population:** ακριβή φίλτρα, URL, συναίνεση όπου ισχύει, χρονική ζώνη και coverage· ίδια και στις δύο περιόδους …
- **evidenceFloor:** 30 ανά περίοδο αν παραλειφθεί. Για ποσοστό/p75: ποιο υποκείμενο πλήθος; …

## Όρια προστασίας (`guardrails`)

Δώστε τουλάχιστον ένα. Για κάθε όριο: metric, συγκεκριμένο threshold με μονάδα/μέθοδο ελέγχου και source.
Εξετάστε LCP/CLS/INP, αναγνωσιμότητα, crawlability, σφάλματα και συντακτική ποιότητα.
Μην ορίσετε «error rate» από απλά sampled `js_error` totals χωρίς έγκυρο παρονομαστή.

## Περίοδοι και συγχυτικοί παράγοντες

- **baselinePeriod:** start `YYYY-MM-DD` … / end `YYYY-MM-DD` …
- **comparisonPeriod:** start `YYYY-MM-DD` … / end `YYYY-MM-DD` …
- **Έλεγχος περιόδων:** ίσο μήκος με συμπεριλαμβανόμενα άκρα, baseline πριν από comparison, χωρίς κοινή ημέρα …
- **Ωρίμανση για COMPLETED:** το τέλος comparison απέχει τουλάχιστον GA4 4 / GSC 3 / RUM 4 / repo 0 ημέρες από σήμερα στην America/Los_Angeles· ισχύει το μεγαλύτερο lag από primary και guardrails …
- **confounders:** αγωνιστικό Σαββατοκύριακο, μεγάλη είδηση, δημοσίευση, Google update, πρόγραμμα· τι ισχύει; …
- **Παράλληλα RUNNING:** υπάρχει ίδια URL/primary metric με κοινή ημέρα σε baseline ή comparison; …

Μελλοντικές/ανώριμες περίοδοι επιτρέπονται στις PROPOSED, APPROVED, RUNNING και PAUSED.
Η ωρίμανση απαιτείται μόνο για COMPLETED· INCONCLUSIVE και ROLLED_BACK μπορούν να καταγραφούν νωρίτερα.

## Απόφαση και επαναφορά

- **decisionPolicy:** πότε διατηρούμε, παύουμε ή επαναφέρουμε; Χωρίς επαρκές πλήθος σε κάθε περίοδο ή έγκυρα guardrails: INCONCLUSIVE. Ποιος αποφασίζει; …
- **failureModes:** τι μπορεί να πάει στραβά; …
- **rollback:** ακριβές αρχείο/στοιχείο και προηγούμενο diff που επαναφέρουμε, βήματα, έλεγχοι και PR/commit επαναφοράς …

## Έγκριση και καταγραφή

- **Αρχικό status:** PROPOSED
- **Πρώτο history entry:** status PROPOSED / date … / actor … / note …
- **pr:** σύνδεσμος PR αυτού του repo ή `null` …
- **commit:** πλήρης σύνδεσμος commit αυτού του repo ή `null` …
- **Έγκριση από άνθρωπο:** προσθήκη APPROVED με date/actor/note και PR ή commit …
- **Πραγματική έναρξη:** ξεχωριστή προσθήκη RUNNING με date/actor/note και PR ή commit …

Δεν μεταβάλλουμε προηγούμενο history, ID ή υπόθεση για να ταιριάξει με ένα αποτέλεσμα.
Περίπου 5 consented επισκέπτες/ημέρα: πριν/μετά είναι παρατηρησιακό και συνήθως INCONCLUSIVE.
Δεν εγκρίνεται αυτόματα δημοσίευση, GA4/tracking αλλαγή, εξωτερική ανάρτηση ή πραγματικό A/B.
